# Lesson 02: Be specific

## The technique

Vague requests get vague answers. Replace broad words ("good", "short", "help me with") with **measurable details**: number of items, length, audience, goal, and what "done" looks like.

## Weak prompt

```
Write a post about my project.
```

## Strong prompt

```
Write a LinkedIn post (under 120 words) announcing my new GitHub repo
"prompt-engineering-from-zero", a beginner course with weak-vs-strong
prompt examples. Tone: friendly and humble. End with a question that
invites beginners to share their biggest prompting struggle.
```

## Why it works

- **Platform and length** are fixed (LinkedIn, under 120 words)
- **Subject** is concrete (repo name and what it contains)
- **Tone** is named
- **Call to action** is defined

Every detail you add removes one guess.

## Quick checklist

- [ ] Who is the audience?
- [ ] How long should it be?
- [ ] What tone?
- [ ] What is the goal of the answer?
- [ ] What should it include or avoid?

## Template

```
Write a [type] for [audience] about [topic].
Length: [number].
Tone: [tone].
Must include: [items]. Avoid: [items].
```

## Try it yourself

Take a vague prompt and add numbers: how many, how long, how detailed. Compare the outputs.
